# الحل المجاني الذي لا يحتاج جهازًا ولا بطاقة: **Render** + تسجيل عناوينه في لوحة Nexus

> **لماذا هذا هو الحل؟**
> خدمة Render المجانية (بلا بطاقة بنكية) تُخرج **كل** نداءاتها من **عناوين IP ثابتة ومنشورة** لكل منطقة. نرفع ريلايّنا عليها، ثم **تسجّل أنت تلك العناوين في لوحة Nexus** (نفس المكان الذي سجّلت فيه العنوان سابقًا — بلا أي تواصل معهم). بعدها يستطيع موقعنا على Vercel الوصول إلى الإنتاج `api.nexusggr.eu` — بلا سيرفر، بلا جهاز يبقى شغّالًا، بلا مال.
>
> الحزمة جاهزة ومُختبرة في مساحة العمل: مجلد **`relay/render-relay/`** ← `relay.js` + `package.json` + `render.yaml`.

---

## الخطوة 1 — GitHub (مجاني، بلا بطاقة) — 3 دقائق
1. أنشئ حسابًا على `github.com` (بريدك فقط).
2. زر **+** أعلى اليمين → **New repository** → الاسم: `forzza-relay` → **Private** → Create.
3. في الصفحة الجديدة: **uploading an existing file** → اسحب الملفات الثلاثة: `relay.js` · `package.json` · `render.yaml` → **Commit changes**.
   *(النسخ من مساحة العمل: افتح كل ملف، حدّد الكل، انسخ، ثم في GitHub «Create new file» والصق.)*

## الخطوة 2 — Render (مجاني، بلا بطاقة) — 4 دقائق
1. `render.com` → **Get Started** → **GitHub** (تسجيل بحسابك — الخطة المجانية لا تطلب بطاقة).
2. **New** → **Blueprint** → اختر مستودع `forzza-relay` → Render يقرأ `render.yaml` تلقائيًا (Free · Frankfurt) → **Apply**.
   - البديل اليدوي: **New → Web Service** → اختر المستودع → Region: **Frankfurt** · Instance Type: **Free** · Build: `npm install` · Start: `node relay.js`.
3. سيطالبك بإدخال **`RELAY_KEY`** (المتغيّر السري) — ضع مفتاحًا طويلًا من عندك (32 حرفًا أو أكثر) واحفظه عندك.
   - `TARGET_URL` مضبوط مسبقًا على `https://api.nexusggr.eu` · `BIND=0.0.0.0`.
4. انتظر حتى تصبح الحالة **Live** (دقيقة–دقيقتان)، ثم افتح:
   `https://<اسم-الخدمة>.onrender.com/healthz`
   ⇒ ستظهر: **`egressIp`** (العنوان الحالي) و`target` و`uptimeSec`.

## الخطوة 3 — انسخ عناوين Render وسجّلها في لوحة Nexus (بلا تواصل معهم)
1. في Render: افتح خدمتك → زر **Connect** أعلى اليمين → تبويب **Outbound** → انسخ **قائمة العناوين/النطاقات** (Render ينشرها لكل منطقة).
2. في لوحة Nexus → **قائمة سماح الـIP** (نفس الصفحة التي سجّلت فيها العنوان سابقًا) → أضف:
   - **كل** العناوين الظاهرة في تبويب Outbound (الأفضل)، أو
   - إن سمح بخانة واحدة فقط: أضف العنوان الظاهر في `healthz` (وهو من نفس المجموعة).
3. ⚠️ مهم: Render قد يستخدم **أي عنوان من المجموعة**، لذلك إضافة **القائمة كاملة** أضمن. وإن كانت اللوحة تقبل **CIDR** (مثل `18.156.0.0/16`) فأضف النطاق كما هو منشور.

## الخطوة 4 — أبقِ الخدمة مستيقظة (Render المجاني ينام بعد 15 دقيقة خمول)
1. `cron-job.org` (مجاني، بلا بطاقة) → أنشئ Job:
   - URL: `https://<اسم-الخدمة>.onrender.com/healthz`
   - Schedule: **every 5 minutes**
2. لماذا؟ الخدمة النائمة تعني **بطء أول طلب ~50 ثانية** عند فتح لعبة؛ التنبيه كل 5 دقائق يمنع النوم (والاستهلاك يبقى داخل حدّ 750 ساعة شهريًا لخدمة واحدة).

## الخطوة 5 — أرسل لي سطرين وأكمل أنا
```
1) https://<اسم-الخدمة>.onrender.com
2) RELAY_KEY=<المفتاح الذي وضعته>
3) (اختياري) لقطة/نص عناوين Outbound التي سجّلتها
```
سأضبط في Vercel: `NXGGR_RELAY_URL` · `NXGGR_RELAY_KEY` · `NXGGR_API_URL=https://api.nexusggr.eu` · `NXGGR_AGENT_CODE=Hatem_TND` · `NXGGR_TOKEN=<الإنتاجي>` ثم **Deploy #9 بموافقتك** (تراجع #8 `…k3w4pyavp…` في ثوان).

## ماذا نفحص فورًا بعد التسجيل (كله قراءة فقط)
| الأمر | ماذا يكشف |
|---|---|
| `provider_list` | **كل المزوّدين المتاحين لحسابك الإنتاجي** |
| `game_list` (بلا فلتر) | حجم الكتالوج الفعلي للسلوتس على الإنتاج |
| `game_list&provider_code=EVOLUTION/PP_LIVE_PRO/EZUGI/…` | **أي استوديو لايف مُفعَّل فعلًا** لحسابك |
| `money_info` | رصيد الوكيل (متوقع 0 — لا يمنع الفحص) |

## ⚠️ نقطتان بصراحة (تخصّان المال والتوقّعات)
1. **بلا رصيد ≠ لا يمكن اللعب عندنا:** المحفظة Seamless ⇒ أموال اللاعبين في قاعدة بياناتنا، ورصيد الوكيل عند Nexus يخصّ **التسوية** الدورية. لكن قد يمنع المزوّد الإطلاق إذا رصيد الوكيل صفر — سنعرف بالضبط بعد أول `money_info` ومحاولة إطلاق **ديمو** (بلا مال).
2. **تفعيل استوديوهات اللايف لحسابك** قرارٌ عندهم. إن كان مُفعَّلًا فسنراه فورًا بعد التسجيل؛ وإن لم يكن، فالبديل بلا تواصل معهم هو صفحة **Products/Sections** في اللوحة (قد تكون ذاتية) — وإلا يبقى البند معلّقًا حتى تتغيّر الظروف.
